# next.md — план развития ЦОР до идеального состояния

> ЦОР — **Цифровой образовательный ресурс**. Это персональный сайт-портфолио магистранта
> (Савчишен А.А.), куда автор сам через код добавляет предметы и выполненные задания.
> **Не** мультипользовательская LMS: без авторизации, профилей, личных кабинетов.
>
> Документ — честный разбор текущего состояния и приоритизированный список улучшений.
> Составлен по итогам разработки (этапы 0–5 + полировка). Цель — довести проект до
> идеального состояния без «мусорных» задач.

---

## 1. Где мы сейчас (факт)

**Стек.** Next.js 15 (App Router) + TypeScript + Prisma + SQLite. Один Node-процесс на :3002
(PM2 + Nginx reverse-proxy). Дизайн-система перенесена из старой статики в `app/globals.css`
дословно + CSS-модули (`course.module.css`, `home.module.css`, `icons.module.css`). Иконки —
lucide-react. Светлая тема по умолчанию, тёмная работает, адаптив 360→1920 проверен.

**Маршруты.** `/` (профиль + сетка предметов), `/subjects/[slug]` (страница курса),
`/showcase/igrovye-osnovy` (премиум-витрина ЦОР), `/api/progress` (статусы «прочитано»).

**Контент — файлами в репозитории, но НЕОДНОРОДНО:**
- Предмет 1 «Разработка цифрового образовательного контента»: 13 заданий — **сырые
  HTML-фрагменты**, извлечённые из старой `index.html` (`scripts/extract-tasks.mjs`), с
  классами старого дизайна. Интерактив (вкладки, видео-слоты, лайтбокс) оживляется в `TaskBody`.
- Предмет 2 «Проектирование образовательных систем»: 6 этапов — **markdown → HTML**
  (`scripts/build-proektirovanie.mjs`, marked) + блок-компоненты React (демо, тренажёры, банк,
  проверка согласованности, dashboard).
- Витрина ЦОР — **статическая копия** старого `course.html` в `public/showcase/` (своя
  дизайн-система `course.css`, свои `hero3d.js/course.js/fx.js`).

**БД.** Только `TaskProgress` (subjectSlug+taskId → status «прочитано»). Состояние общее
(не на пользователя) — это сознательное решение для персонального сайта. `StudentProfile` в
схеме есть, но редактирования нет; по сути это статические дефолты.

## 2. Главный технический долг (приоритет 1)

### 2.1. Унифицировать модель контента
**Проблема.** Сейчас три разных способа подачи контента (HTML-фрагменты / markdown / статика).
Добавление нового предмета требует выбора способа, ручных скриптов и разной разметки.
**Решение.** Единый pipeline на **MDX** (`@next/mdx` или `next-mdx-remote/rsc`): контент темы —
`.mdx`, в который можно встраивать общие React-компоненты (Callout, Quiz, Trainer, VideoSlot,
Table). Старые HTML-фрагменты предмета 1 постепенно перевести в MDX (или оставить как
`legacy-html`-вариант рендера, но описать это явно).
**Зачем.** Один предсказуемый способ авторинга → быстрее и чище добавлять предметы.
**Объём.** Средний/большой.

### 2.2. Перенести витрину ЦОР в React
**Проблема.** `/showcase/igrovye-osnovy` — изолированная статика: дублирует шрифты, свою
тему-переключалку, свой ambient-фон; не делит дизайн-систему с платформой; 3D/тест на vanilla JS.
**Решение.** Компоненты `HeroScene` (Three.js через CDN с 2D-фолбэком), `LoopDemo` (canvas),
`QuizTest` (React-состояние), секции витрины как MDX. Премиум-CSS заскоупить под `.showcase`.
**Зачем.** Единая тема/навигация, меньше дублирования, проще поддерживать.
**Объём.** Большой. **Можно отложить** — сейчас витрина работает корректно.

### 2.3. Упростить профиль студента
**Проблема.** `StudentProfile` (Prisma-модель + `getStudentProfile`, создающий строку в БД) —
избыточен: редактирования нет, данные статичны.
**Решение.** Заменить на статический конфиг `lib/student.ts` (объект). Убрать модель из схемы.
**Зачем.** Минус неиспользуемая сложность и обращение к БД на главной.
**Объём.** Маленький.

## 3. Качество и доступность (приоритет 2)

### 3.1. Accessibility-аудит интерактива
Тренажёрам добавить ARIA: `role="group"`/`aria-pressed` для кнопок «Условие/Цикл», `aria-live`
для блоков обратной связи, фокус-стили. Лайтбоксу — ловушку фокуса и возврат фокуса. Проверить
порядок табуляции в раскрытых заданиях. Прогон по axe/Lighthouse a11y.

### 3.2. Производительность
- Картинки → `next/image` (сейчас обычные `<img>`): авто-размеры, lazy, оптимизация.
- Почистить `globals.css` (1700+ строк перенесённого CSS — часть правил относится к старой
  разметке и не используется). Удалить мёртвые селекторы аккуратно, со сверкой.
- Шрифты — рассмотреть `next/font` (self-host) вместо Google CDN.
- Видеолекция (114 МБ) — оставить вне git, грузить с сервера; проверить `Accept-Ranges`.

### 3.3. SEO/метаданные
- Динамический `generateMetadata` уже есть для предметов; добавить осмысленные OG-описания.
- Рассмотреть генерацию `og-image` на лету (динамические превью) — сейчас одна статичная.
- `sitemap.xml` сделать генерируемым из `content/` (Next `app/sitemap.ts`), а не ручным.

## 6. Инфраструктура и надёжность (приоритет 2/3)

- **Бэкап `prod.db`.** Файл SQLite не в git; настроить периодическую копию (cron `cp`).
- **Миграции БД.** Сейчас `prisma db push`. При изменениях схемы перейти на `prisma migrate`
  для воспроизводимости.
- **CI (опционально).** GitHub Action: `npm ci && npm run build` на PR — ловить регрессии сборки.
  Можно добавить Lighthouse CI для бюджета производительности/a11y.
- **Аналитика посещений (опционально).** Лёгкий Plausible/Umami, если нужна статистика заходов
  преподавателей (без cookies/персональных данных).

## 7. Сознательные решения (НЕ баги — не «чинить»)

Чтобы будущие правки не сломали задуманное:
- **Нет авторизации/профилей/мультипользовательской логики** — это персональный портфолио-сайт.
- Статус задания — **«Прочитано»** (преподаватель ознакомился), не «Выполнено». Предмет в
  целом помечается «✓ Выполнен» через `meta.studentStatus`.
- Прогресс чтения — **общий** (не на пользователя): для личного сайта это норма.
- Светлая тема — **по умолчанию и приоритет**.
- Старая статика (`_legacy/`) и исходники (`source/`, `proektirovanie/`) — **референс**,
  не часть рантайма.
